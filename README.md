# Voice Accent Trainer & Listener ("fluency+")
#### Video Demo: https://www.youtube.com/watch?v=HUyjcbNCkYs
#### Description:

**Voice Accent Trainer & Listener** (also known as **fluency+**) is an interactive, browser-based web application meticulously designed to help non-native English speakers practice their pronunciation, work on their accent accuracy, and break away from traditional, passive "translation-based" learning methodologies. Traditional language learning applications heavily focus on written mechanics like reading comprehension, vocabulary flashcards, and grammar fill-in-the-blank exercises. While these methods build a strong theoretical foundation, they often fail to prepare students for real-time, spoken communication. 

Instead of translating text back and forth in isolation, this application creates a dynamic environment that encourages users to actively speak out loud, delivering immediate, visual feedback on their spoken accuracy. The primary goal is to lower the barrier of entry for language learners who lack native-speaking conversation partners, allowing them to practice speaking anytime, anywhere in a meditative, low-pressure focus zone that prioritizes the physical act of talking over navigating complex menus.

---

## 🚀 Features

* **Real-Time Speech Recognition:** Utilizes the advanced native Web Speech API to listen to user speech with zero lag, ensuring an instantaneous loop between vocalization and visual feedback.
* **Accent Forgiveness Loop:** Scans the top 5 alternative linguistic guesses generated by the underlying speech engine. This allows the application to accommodate unique regional accents and minor pronunciation variations without discouraging the learner.
* **Dynamic Text Highlighting:** Automatically parses user-input text and highlights the currently expected word using interactive `<mark>` HTML cues, guiding the user visually through the sentence.
* **Session Control:** Complete playback control with dedicated Play, Stop, Restart, and Manual Skip capabilities to ensure full autonomy over the practicing session.

## 📁 File Structure and Architecture

The project is structured cleanly to keep frontend assets, visual layout, and interface logic separated and easily maintainable. Below is a detailed breakdown of the core files included in this submission:

* **`index.html`:** The primary interface of the application. It contains the essential layout for the application's workspace, featuring the main text input area, the text prompt display window, control buttons, and clear indicators for microphone status. It utilizes semantic HTML5 tags to ensure accessibility and structural responsiveness across desktop viewports and mobile devices.
* **`listener.js`:** The core engineering engine of the application. This script handles the primary application logic, interacting directly with the browser's `SpeechRecognition` API. It manages microphone states, captures audio segments, processes the confidence intervals of the speech engine, handles the automated incrementing loops, and dynamically updates the DOM elements without requiring a page refresh.
* **`CNAME`:** A configuration file mapping the custom domain configuration for deployment, allowing the application to live publicly on the web.

## ⚙️ How It Works

1. **Input:** The user pastes any English text, paragraph, or essay into the main textarea configuration.
2. **Initialization:** Clicking the **Play** button initializes the browser's internal speech recognition engine and requests microphone permissions.
3. **Active Practice:** The user reads the explicitly highlighted word aloud into their microphone.
4. **Validation:** If the user's spoken pronunciation matches one of the API's top 5 internal confidence guesses, the JavaScript application automatically increments to the next word and shifts the highlight framework forward.
5. **Manual Navigation:** The user can utilize the **Skip** button to manually pass highly problematic words, homophones, or names that the local speech recognition engine might consistently struggle to parse.

## 💡 Technical Design Choices & Challenges

During the architecture and development of this project, several core design choices were debated, particularly regarding speech processing efficiency and user interface psychology.

### 1. Client-Side API vs. Server-Side Audio Processing
Initially, the conceptual plan involved streaming captured microphone audio from the user's browser directly to a backend server (such as a Python Flask instance), processing the audio data using a server-side machine learning library, and returning accuracy metrics. However, initial prototyping showed that this approach introduced noticeable network latency, required massive server overhead, and complicated deployment due to varied audio compression formats across different browsers (such as Safari's strict media constraints versus Chrome's native WebM formatting).

To optimize performance, the architecture shifted toward entirely client-side processing using the native Web Speech API. By leveraging the Web MediaDevices layer locally, the application responds instantly to user input, eliminates server bandwidth bottlenecks, and keeps the deployment infrastructure incredibly lightweight and fast.

### 2. The "Accent Forgiveness Loop" Innovation
One of the biggest obstacles discovered during early testing was that strict 1:1 text matching severely discouraged users with strong non-native accents. If the speech engine recognized "hello" as "helo" or "hallo", the application would stall completely. To solve this, the processing loop was re-engineered to inspect the deep results array returned by the `SpeechRecognition` event. By looping through the top 5 alternative text hypotheses instead of just checking the primary result, the app drastically increased usability for language learners while preserving the core focus on verbal fluency.
